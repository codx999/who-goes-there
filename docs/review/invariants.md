# Invariants: the rules a review must check

One row per rule that must always hold. `/review-session` selects rows whose "where" column
matches a changed path (prefix or glob) or a passed item id and gives the scenario to the
reviewers as focus, not as a limit. "none yet" in the test column is a visible gap: fill it with
the item that builds the module, naming the test file. Cite documents by section, not line. When a
rule changes in its source document, update the row in the same commit. `tests/test_risk_files.py`
checks that every path in the "where" column is matched by `scripts/risk_files.sh` (R44): write
paths and globs in backticks, item ids as plain numbers, and keep everything else out of that
column. One table, so `grep -c '^|'` counts header, separator and rows (item 2.01).

Sources: CLAUDE.md ground rules (CL); `docs/plan.md` by section (PL §n), which wins over every
other document; `docs/setup-playbook.md` (SP); `.claude/rules/data.md` (DR) and
`.claude/rules/training.md` (TR); Beery et al. 2018 (BE). Documents are tier 0 by design: a change
to a cited document is reported as "spec changed" at every tier, including 0.

Id ranges: R01 to R07 what never enters git and what may be shown; R10 to R17 splits, leakage and
test-set isolation; R20 to R27 transforms, boxes and the experiment; R30 to R38 model, training,
evaluation, demo and Space; R40 to R45 actions with no diff and the control plane.
